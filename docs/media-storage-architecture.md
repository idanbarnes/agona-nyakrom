# Media Storage Architecture

Agona Nyakrom uses one unified Express runtime:

- `/` serves the public frontend
- `/admin` serves the admin frontend
- `/api` serves backend routes
- `/uploads` serves legacy local media files

## Storage Modes

`MEDIA_STORAGE` supports two values:

- `local`
- `cloudinary`

Development and test runtimes default to `local` when `MEDIA_STORAGE` is omitted.

Production runtimes default to `cloudinary` when `MEDIA_STORAGE` is omitted. Production means `NODE_ENV=production` or a hosted Render runtime. If production is configured with `MEDIA_STORAGE=local`, startup fails unless `ALLOW_PRODUCTION_LOCAL_UPLOADS=true` is set.

## Local Development

Local uploads use `backend/uploads` unless `UPLOAD_DIR` points somewhere else. New uploads are first written under `uploads/tmp`, then `mediaService` processes image variants into section folders such as:

- `uploads/news`
- `uploads/obituaries`
- `uploads/homepage`
- `uploads/carousel`

Database values for local media are stored as relative upload paths such as:

```text
uploads/news/news-example-original.webp
```

Frontend rendering resolves those values through `/uploads/...`.

## Production

Production media should use Cloudinary:

```env
MEDIA_STORAGE=cloudinary
CLOUDINARY_CLOUD_NAME=...
CLOUDINARY_API_KEY=...
CLOUDINARY_API_SECRET=...
CLOUDINARY_BASE_FOLDER=agonanyakrom
```

When Cloudinary is enabled, processed variants are uploaded to Cloudinary and the database stores absolute delivery URLs returned by Cloudinary. Existing absolute Cloudinary URLs are preserved by backend and frontend URL resolution.

## Legacy `/uploads` Support

The unified runtime still serves `/uploads` for local and legacy media compatibility. This is required for existing records that still point at local upload paths.

`/uploads/tmp` is not publicly served. Temporary upload files are implementation details and must not be used in public content, SEO metadata, or admin-only records.

## Upload Processing

Admin upload routes use Multer to accept image files into `uploads/tmp`. The accepted MIME types are:

- `image/jpeg`
- `image/png`
- `image/webp`

Uploads are limited to 5 MB. Temporary filenames are sanitized before disk write. Final managed image names are generated by `mediaService`, not from user-provided filenames.

## URL Rules

- Local upload references resolve through `/uploads/...`.
- Cloudinary `https://res.cloudinary.com/...` URLs remain absolute.
- Loopback local upload URLs are normalized back to `/uploads/...`.
- SEO/social image resolution excludes `/admin`, `/api`, `/preview`, and `/uploads/tmp`.

## Production Override

`ALLOW_PRODUCTION_LOCAL_UPLOADS=true` allows local disk uploads in production. This is an explicit risk acceptance switch for temporary or self-managed persistent disk deployments. Do not use it for ephemeral hosted production unless the data loss risk is understood.
